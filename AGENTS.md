Project goal: The project is a small-scale LLM research framework for testing novel model architectures under tightly controlled conditions. The immediate focus is on ~10M-parameter decoder-only language models, with the option to scale promising ideas to ~100M and eventually ~1B parameters. The objective is not merely to minimize validation loss, but to compare architectures on training efficiency, stability, throughput, memory use, and general-language benchmark performance using a fixed dataset, tokenizer, training protocol, and evaluation suite. Successful base models can later be extended with instruction and chat post-training to test whether architectural gains persist in practical conversational models.

Environment: Ubuntu 24.04 on a Ryzen 9 7950X3D with 64 GB RAM and a Radeon RX 7900 XTX. The active project environment uses Python 3.12.3 and PyTorch 2.13.0+rocm7.2 with HIP 7.2. The dataset is a ~500M-token subset of HuggingFaceTB/smollm-corpus, sampled proportionally from FineWeb-Edu, Cosmopedia v2, and Python-Edu according to the original 220B:28B:4B mixture. That raw subset is frozen, then tokenized with a custom byte-level BPE tokenizer with an 8,192-token vocabulary. The tokenizer reserves <pad>, <unk>, <bos>, <eos>, <|system|>, <|user|>, <|assistant|>, <|end_turn|>, <|reasoning|>, and <|end_reasoning|> for future post-training use. The tokenized corpus is split deterministically at document level into 90% train and 10% eval, stored as flat uint16 token streams.

Training regimen: Models use a fixed context length of 2048 and initially train for one epoch over the current 527.9M-token training stream. The optimizer baseline is AdamW with betas=(0.9, 0.95), eps=1e-8 with FP32 optimizer states, weight decay 0.1, gradient clipping at 1.0, and no dropout. Effective batch size is fixed at approximately 128k tokens per optimizer step using gradient accumulation as required by VRAM. Peak learning rate is selected by a short sweep, initially testing roughly 3e-4, 6e-4, 1e-3, and optionally 2e-3, using linear warmup for about 1–2% of training followed by cosine decay to roughly 10% of peak LR. Validation is run every 250 optimizer steps, checkpoints are saved every 500 steps plus at the end, and early architecture comparisons use one fixed seed before promising designs are rerun across multiple seeds. Weight initialization starts from a normal distribution with std=0.02, with GPT-style residual output scaling where applicable. Base models are evaluated with held-out validation loss/perplexity plus zero-shot HellaSwag, PIQA, ARC-Easy, BoolQ, and LAMBADA (lambada_openai).

Future experiments: Once the baseline is stable, we can vary the optimizer and precision strategy, including alternatives such as Lion, Sophia, Adafactor, Muon, and 8-bit optimizer states for larger models where FP32 AdamW becomes VRAM-heavy. We can also experiment with learning-rate schedules, warmup fractions, effective batch sizes, dropout/regularization, initialization schemes, tokenizer vocabulary size and eventually more experimental tokenizer designs. At larger model scales, especially around 100M parameters and above, it may also make sense to revisit the tokenizer size, training-token budget, number of epochs, and benchmark suite, adding harder evaluations such as MMLU once the models are capable enough for those scores to be informative.
